# G031: On-Premises to VPC Over the Internet With a 99.99% Availability SLA (HA VPN + Cloud Router)

**Topic:** Hybrid networking (HA VPN)

## ❓ Question
> You need encrypted connectivity between your on-premises data center and your VPC over the public internet. The business requires a 99.99% availability SLA, and routes should update automatically when networks change. What should you do?
>
> **A.** Create an HA VPN gateway with two tunnels to your on-premises VPN devices, and use Cloud Router with BGP for dynamic routing.
>
> **B.** Set up VPC Network Peering between the VPC and the on-premises network.
>
> **C.** Order a Dedicated Interconnect connection in a single location.
>
> **D.** Create a Classic VPN gateway with one tunnel and static routes.

**My answer:** — (not tried yet)
**Correct answer:** A
**Result:** ⏳ Not tried yet

## 📖 What the Question Is Asking

**In plain words:**
- **The situation:** Your office data center (on-premises) must connect privately to your Google Cloud network (VPC), using the public internet with encryption.
- **What you must achieve:** Get a connection with a 99.99% availability guarantee (SLA: the uptime Google promises), where routes (network paths) update automatically.
- **The limits:** It goes over the internet, so no private fiber line is required.
- **What they're really asking:** Which Google Cloud VPN option gives 99.99% and automatic routing?

**Clues in the question:**
- "**encrypted … over the public internet**": **Cloud VPN**.
- "**99.99% availability SLA**": **HA VPN** (two interfaces, two tunnels). Classic VPN offers 99.9%.
- "**routes should update automatically**": **Cloud Router with BGP** (dynamic routing).

**Exam topic:** Hybrid connectivity (exam guide section 2.3).

---

## 📚 Key Terms Explained

### 1. HA VPN 🔑
- **What it is:** High-availability Cloud VPN: a gateway with **two interfaces** (two public IPs). With tunnels from both interfaces to your peer devices, Google offers a **99.99%** SLA. It requires BGP via Cloud Router.
- **Looks like:** `gcloud compute vpn-gateways create shop-havpn --network=shop-vpc --region=us-central1` + 2 tunnels + `gcloud compute routers create shop-router --asn=65001`
- **Not to be confused with:** Classic VPN (one interface, 99.9% SLA, static routing allowed), or Interconnect (a private physical link).
- **Analogy:** 🛣️ Two separate roads to the warehouse, so one closure doesn't stop deliveries.
- **In the online store:** The office ERP talks to cloud orders over HA VPN.

### 2. Cloud Router / BGP
- **What it is:** A managed router that exchanges routes with your on-prem router using BGP (Border Gateway Protocol), so new subnets are learned automatically.
- **Looks like:** Cloud Router ASN 65001 ↔ on-prem ASN 65010, advertises `10.10.0.0/16`
- **Not to be confused with:** Static routes you type by hand.
- **Analogy:** 📡 Two dispatchers who share road updates automatically.
- **In the online store:** New ShopNow subnets reach the office with no manual change.

### 🔗 How they fit together
```
 On-prem router A ═tunnel 1═╗
                            ╠═ HA VPN (2 interfaces) ─ Cloud Router (BGP) ─ VPC ✅ 99.99%
 On-prem router B ═tunnel 2═╝
```

## 🌍 Real-World Scenario

A retailer's warehouse system on-prem must reach cloud order APIs at all times. **HA VPN** with two tunnels and BGP survives a tunnel or device failure, and new cloud subnets appear on-prem automatically.

---

## 🔍 Option-by-Option Breakdown

### ✅ A
> **A.** Create an HA VPN gateway with two tunnels to your on-premises VPN devices, and use Cloud Router with BGP for dynamic routing.

**Why it's correct:**
- ✔️ "**HA VPN gateway with two tunnels**" matches "**encrypted … over the public internet**" and "**99.99% availability SLA**".
- ✔️ "**Cloud Router with BGP for dynamic routing**" matches "**routes should update automatically**".

📌 **When to use it:** Use it when your office must stay securely connected to the cloud over the internet with very high uptime.
🏢 **Office example:** Two separate roads to the warehouse, with dispatchers sharing road updates automatically.

### ❌ B
> **B.** Set up VPC Network Peering between the VPC and the on-premises network.

**Wrong words:**
- ❌ "**VPC Network Peering … on-premises network**": peering connects two VPC networks in Google Cloud, not an on-prem data center.

📌 **When to use it:** Use peering to connect two VPCs privately.
🏢 **Office example:** A connecting door between two offices in the same building.

### ❌ C
> **C.** Order a Dedicated Interconnect connection in a single location.

**Wrong words:**
- ❌ "**Dedicated Interconnect**": a private physical link, not over the internet, with longer lead time. And "**single location**" doesn't meet 99.99%.

📌 **When to use it:** Use Interconnect for high bandwidth over private links.
🏢 **Office example:** Building your own private road.

### ❌ D
> **D.** Create a Classic VPN gateway with one tunnel and static routes.

**Wrong words:**
- ❌ "**Classic VPN … one tunnel**": at most 99.9%, with a single point of failure.
- ❌ "**static routes**": routes don't update automatically.

📌 **When to use it:** Use it only for simple, non-critical links (Classic VPN is legacy).
🏢 **Office example:** One road to the warehouse, with handwritten directions.

## 🛒 E-Commerce Full-Stack Example

**ShopNow**: HA VPN `shop-havpn` (2 tunnels) ↔ office routers A and B; Cloud Router `shop-router` ASN 65001 advertises `10.10.0.0/16`. The warehouse ERP reaches `orders-api` internally.
